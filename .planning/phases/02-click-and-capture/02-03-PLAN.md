## Phase Goal

**As a** pianist drilling a passage alone, **I want to** play it many times to a metronome and have every repetition recorded as raw MIDI that nothing can lose, **so that** later phases can tell me what I keep getting wrong from data I trust.

<objective>
Turn one long recording into numbered repetitions: B7+C8 (or the spacebar) between passes writes a marker into the raw stream, the session panel lists "Pass N - K notes" as the user plays, and closing the tab mid-drill and reopening shows the same passes with the same counts. The marker detector and the pass segmenter are pure, node:test-pinned functions over plain records, so Phase 3 reads passes from the same code the UI does.

Purpose: roadmap success criteria 3 and 5 — one action splits the session, and a real 10+ pass drill comes back intact. The pass is the unit every later phase aggregates over; its boundaries must be unambiguous and its contents complete (D-03, D-04, D-07).

Output: src/pass-marker.js, src/pass-segmenter.js, marker/pass wiring and the pass list in src/capture-app.js and index.html, the run-path gate extended, the headless round trip extended to mark passes and reload mid-session, test/pass-marker.test.cjs, test/pass-segmenter.test.cjs.
</objective>

<assumption_delta_decision>
Primary noun: the pass boundary — a `type: 'marker'` record in the session's raw event stream carrying `source`, `timeStamp` and `seq`.
Decision: promote. The roadmap phrased the marker as a configuration choice (spacebar, a chosen MIDI key, or the sustain pedal); CONTEXT D-01/D-02 fixed the gestures (B7+C8 pair and spacebar, never the pedal) and D-07 fixed what a boundary is (timestamp plus stream position). The general representation — one boundary record in the raw stream, produced by either gesture — is therefore primary; the key pair and the spacebar are two producers tagged by `source`, and the segmenter, the pass list, Phase 3 and Phase 5 read boundaries from that one place. The key pair remains a stored setting (`markerKeys`) as D-01 requires, so changing keys never changes the boundary shape. No old representation is kept alongside, so no debt is accepted.
Invariant test (included in test/pass-segmenter.test.cjs): for events written live with `passOrdinal`, every non-marker note-on in `segment(...)` pass N carries `passOrdinal === N`.
</assumption_delta_decision>
